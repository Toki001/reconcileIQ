# Free-only Gemini operations

The adapter uses official `google-genai` (locked 2.32.0) with **gemini-3.5-flash-lite** and the Gemini Developer API endpoint. No paid model, Vertex, enterprise path, automatic model substitution or billing-enabling operation exists. The model's official pricing lists free-tier input/output; API success alone does not prove project eligibility. Free-tier submissions may be used to improve Google products: only repository-labelled synthetic PDF digests are admitted.

Current verification status: **live AI unavailable**. The user selected an existing Free Tier project and will provide its ID/configuration. No project ID, Gemini key or read-only verification credentials were available at implementation time. No cloud generation, token-counting or model-listing requests have been made. Do not interpret offline test providers as live Gemini performance.

## Local configuration and proof

Run `python3 scripts/setup_env.py`; existing secrets are preserved. Put backend-only `RECONCILE_AI_API_KEY`, `RECONCILE_AI_PROJECT_ID` and `RECONCILE_AI_ENABLED=true` in the private root environment. Never paste a key in chat, commit it, use `NEXT_PUBLIC_`, or place it in frontend configuration. The only allowed endpoint/model are the reviewed defaults in `.env.example`.

Verification also requires independent Application Default Credentials able to perform read-only project lookup, Cloud Billing `projects.getBillingInfo`, API Keys `lookupKey` and Service Usage quota metric reads. The adapter requires the returned key parent to match the intended project's number, explicitly disabled billing with no linked billing account, model-specific positive free-tier request quotas per minute/day, and the official SDK model listing to advertise `generateContent` for the exact model. Missing permissions, new auth-key formats unsupported by key lookup, unexposed quota dimensions or any ambiguous response leave AI unavailable. No manual `billing_disabled=true` assertion bypasses proof.

ADC must exist in each backend/worker runtime. Compose intentionally does not mount arbitrary host credential directories. If supplying a read-only ADC file, use a private local Compose override that mounts only that file read-only and sets `GOOGLE_APPLICATION_CREDENTIALS` for API/worker; never commit it. Do not enable Cloud services or billing to make verification work without reviewing that separate action. The quota API may not expose AI Studio's quota in the required shape; this remains a live compatibility limitation until verified with the actual project.

An admin explicitly calls `POST /v1/ai/verify` with an Idempotency-Key (or **Verify free project** in Invoice Review). It stores an immutable success/failure record and performs no generation. A new key refreshes proof; repeat keys replay the original response. `GET /v1/ai/status` is read-only and does not poll Google. It returns only model, safe status code and check time, never key/project proof details. Proof expires after five minutes. The worker re-checks before every generation. External project/billing changes between checks and a request remain a residual race; this local system cannot lock a Google project against another administrator's changes.

## Bounds and recovery

Defaults: two generation admissions/minute, twenty/day (UTC windows), one concurrent request/project, 20,000 input characters, conservative 6,000 counted input tokens including prompt/schema estimate, 8,192 output tokens, 20-second SDK timeout. Configuration has upper bounds. PostgreSQL counters/expiring leases coordinate processes and cap application usage; configured limits are reduced to verified quota values. Other project users can consume quota independently, so a positive configured limit is not a guarantee of remaining quota.

Model list, read-only verification and token counting are separate bounded preflight requests; the application's counters count generation admissions, not every HTTP request. SDK automatic retries are disabled. Existing worker retries have exponential backoff/jitter and at most five attempts. Numeric and HTTP-date Retry-After are honored; hints beyond 24 hours become permanent/manual failures instead of retrying early. Auth/invalid-model/schema failures are permanent; timeouts/service/quota errors are bounded retries. Repair dependency and admin-replay with a reason. Logical request IDs and durable execution keys prevent duplicate candidate publication across retry/replay.

Provider usage records preserve model/prompt, verified proof, known prompt/output/thought token counts and safe errors. Unknown usage is null. No document content or raw provider/SQL exceptions enter diagnostics. No live cost is fabricated: generation cost can be reported as zero only for actually verified free-tier requests. OCR/infrastructure are accounted separately.

Only a small synthetic live smoke is authorized after every check passes. A larger live golden-set evaluation requires separate permission and available free quota. Never automatically send all 100/200 PDFs.
