## Confirmed defects and scope

Three narrowly scoped corrections preserve the current interfaces and workflows:

1. `to_minor` calculated its upper bound using ambient Decimal precision. At precision six it accepted `MAX_MINOR + 1` for all five currencies. The bound now uses the same explicit local context as scaling/rounding. Five failing boundary regressions reproduced the defect before the fix. Deterministic Hypothesis properties run 200 examples each for exact currency round trips, rational HALF_UP rounding and discounted inclusive/exclusive tax lines. An independent `Fraction` oracle avoids repeating Decimal implementation arithmetic. Accounting source inspection also rejects float literals/conversions; fractional financial inputs continue to reject binary floats.
2. A Celery soft deadline raised inside PDF parsing was caught as permanent `INVALID_PDF`. The parser and orchestration now retain retryable `PROCESSING_TIMEOUT`. A failing parser regression reproduced the classification before the fix; a real Linux prefork soft signal verifies retry and recovery.
3. Worker diagnostic filters missed a percent-decoded broker password and MinIO access key. Reproduced with synthetic credentials, both encoded/decoded broker password forms and the access key are now redacted. Raw exception chains remain suppressed. This extends the mitigation for milestone 03's diagnostic exposure; it does not constitute credential rotation or a production logging/security certification.

Migrations 0001–0006, canonical API contracts, generated clients, queue configuration, financial fixtures and UI implementation remain unchanged. New test-only providers are under `tests/support`; they are never loaded by the application worker. Hypothesis is a development dependency only.

## Remaining limits and Milestone 06 readiness

The existing digital-text foundation has passed the requested milestone 05 gates and is ready for separately requested milestone 06 development. Milestone 06 is not implemented or started automatically. Captured text is sealed **untrusted** evidence and does not populate authoritative money or approve invoices. Reconciliation and supplier-reference processors still fail explicitly as unsupported.

The dashboard remains a read-only auditor interface with synthetic financial views and a real processing panel. Upload, replay and extracted-text inspection do not have dashboard write/view controls. Browser upload checks therefore use real API-assisted admission and MinIO PUT in Playwright's Node process, then verify actual polling and refresh in the browser. There is no claim of a complete end-user upload/reviewer UI. Presentation-only empty/error injection is labelled separately from backend integration. Server-held credentials never enter page JavaScript; credential-bearing browser traces are disabled for these tests.

Financial snapshot filtering continues to operate on the bounded synthetic dashboard records; it is not a new paginated production invoice browser. REST invoice cursors are covered by the existing stable-order/snapshot/query-binding tests; processing cursor navigation is exercised by Jest and the real browser workflow.

No OS-level PDF sandbox, production identity deployment, general request-rate limiter, cross-tenant scheduling fairness proof, production load/soak test, OCR/AI quality evaluation, distributed observability or adversarial exploit campaign is claimed. Active-job backpressure and GraphQL complexity limits are tested; they do not replace perimeter rate limiting. The archived MinIO dependency, credential lifecycle, orphan-object/DLQ retention and backup operations still require production review. Data/worker persistence and bounded retries are demonstrated for the scenarios listed, not arbitrary partitions or indefinite outages. Payments remain prohibited.
