## Interface and security boundaries

The public change is additive `GET /v1/processing-jobs` plus clearer job next-action text. Existing mutation inputs, job states, authentication, roles, signed webhooks and pagination remain compatible. REST types were regenerated; reviewed GraphQL SDL and its generated operation types are unchanged. The original finance views remain synthetic; the added read-only panel polls persistent extraction jobs through a server-held auditor credential. It renders pending dispatch, queued, processing, completed, retrying and failed states without an unauthorized replay control.

Digital text is stored as sealed untrusted extraction evidence. The worker verifies database ownership, sealed-key shape, object metadata, size, signature and digest. It never treats document text as instructions or computes authoritative invoice money. Unsupported OCR, financial extraction, matching and supplier-reference processing do not claim success.

Worker diagnostics redact configured secrets, database/broker passwords and credential-bearing connection URLs, remove raw exception chains, and suppress PDF-parser warning content. Task messages contain organization/job IDs only. These changes directly address the diagnostic exposure documented in milestone 03; they are not a claim of a production identity or credential-lifecycle deployment. The final scan found no generated local credential values in repository candidates, built public Next.js assets or any milestone 04 logs. Environment files, the backup and captured worker log are mode 0600.

## Readiness and limits

Milestone 05 can build on the working processor, durable outbox, lease fencing, retained attempts/failures, explicit terminal publication and replay tests. It has not been started automatically.

Remaining limits: local API-key identity and no end-user dashboard login; digital PDFs only; no OCR, Gemini/LLM provider, financial field extraction or full matching; no strict OS-level parser sandbox; no global tenant scheduling fairness guarantee, production load/soak proof or distributed tracing. The live crash test kills the worker with durably pending work; mid-attempt crash/fencing is separately simulated against both database backends. The 40/60-second limits are configured, not a claim of an exhaustive real hard-timeout fault campaign. Retention for orphan objects and terminal notifications, production broker ACLs, backup operations and the archived MinIO dependency still need operational review. Payments remain prohibited.
