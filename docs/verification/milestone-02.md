## Build adjustments verified during this milestone

GraphQL Code Generator v6's operations plugin generates its own referenced input/enum types; the obsolete combined configuration caused duplicate declarations. The final configuration follows the [official v6 migration guide](https://the-guild.dev/graphql/codegen/docs/migration/operations-and-client-preset-from-5-0), using `typescript-operations` and `typed-document-node`.

Parallel cold Docker dependency downloads stalled. Bootstrap now builds Python before the frontend, limits network concurrency/timeouts and retains BuildKit dependency caches. Python dependency installation precedes source copies, following [uv's workspace Docker guidance](https://docs.astral.sh/uv/guides/integration/docker/). Subsequent source changes reuse locked dependencies. The original MinIO source pin and existing unrelated applications are preserved.

## Scope and limits

Authentication is local organization-scoped API keys with digest storage and revocation checks. There is no production identity provider or end-user dashboard login. The dashboard uses a server-held auditor key and remains bound to loopback. Browser checks use desktop Chrome and a phone viewport, not physical phone hardware.

A 202 response is durable job/outbox admission. New extraction, reconciliation and supplier jobs remain `pending_dispatch`; no business outbox publisher or processing worker is claimed. Seeded completed results are explicitly synthetic. The independent Celery probe demonstrates duplicate-effect suppression only. Job replay creates a new linked execution and retains original history.

PDF completion checks bounded size, MIME, magic bytes and SHA-256, and seals a separate input copy. It does not parse, scan or extract documents. Cleanup of expired uploads/orphan sealed objects remains later retention work. Cursors use an upper watermark and signed keyset positions; they do not provide snapshot isolation over changing filter membership. Idempotency keys are currently retained indefinitely. Currency support is an explicit ISO 4217 subset; tax inputs are checked for arithmetic consistency, not jurisdictional validity.

Review acceptance never authorizes spending or payment. No payment, bank, OCR, LLM or remote-document-fetch integration was added. Full relational financial modeling, extraction, deterministic matching, recovery telemetry and production deployment remain later milestones.
