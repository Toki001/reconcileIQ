# Milestone 07 — CI/CD and Production Container Engineering

Continues `0d3e27d`. Plan recorded before implementation. No public deployment, image publication, live Gemini request, retained data reset or Milestone 08 work is authorized by this milestone.

## Architecture audit

- Root uv workspace/uv.lock (Python 3.12), pnpm 12.10.1/pnpm-lock.yaml (Node 22); Ruff, mypy, pytest/coverage, Jest, Playwright and contract/client/fixture drift tooling already exist. No GitHub workflows exist at baseline.
- Existing multi-stage Python and standalone Next.js Dockerfiles run non-root. Python image serves API, migrations and Celery; Tesseract English and Poppler support restricted PDF/OCR and previews. MinIO builds archived checksum-pinned source. Mutable base tags, shared image identity, missing image-level healthchecks, and absent release procedures need improvement.
- Development Compose has PostgreSQL 17, RabbitMQ, MinIO, migration/seed one-shot, API, worker and web; loopback ports and named volumes. Recovery/dispatch is a supervised Celery bootstep with fenced PostgreSQL claims, not a separate service. Preserve that design.
- Migrations 0001–0007, reviewed OpenAPI 3.1/GraphQL SDL and generated TypeScript clients are already verified. No schema change is planned. API readiness checks database/schema, RabbitMQ and MinIO; storage creates its bucket idempotently.
- Local role-key authentication and encrypted browser sessions are not production identity. Settings currently reject production environments. The release example must retain this fail-closed boundary and expose no public data/admin ports. Parser/OCR limits do not provide a hostile-document sandbox.
- Gemini official SDK/model remain intact and disabled. Reference project `gen-lang-client-0088737565` is not proof of key binding, billing or free quota. CI uses mocks and no cloud credentials.

## Plan

1. Pin build inputs; reuse Python runtime with distinct API/worker targets, healthchecks and graceful termination. Harden build context.
2. Add separate private production-style Compose example with explicit migration profile, named volumes, resource bounds, no public infrastructure ports and rejected production authentication mode.
3. Add least-privilege, SHA-pinned PR CI and separately gated/manual GHCR release preparation; never publish from PRs. Scan dependencies/images/secrets and preserve reports without sensitive artifacts.
4. Verify fresh/populated-copy migrations, backup restore, old-image compatibility, worker restart with pending work, Docker runtime/OCR and existing regressions. Preserve original 5,964 rows and all 6,802 rows captured at milestone start.
5. Write deployment/rollback/security runbooks, record actual evidence and blockers, and commit only after required local checks pass.

## Delivered release engineering

The existing development Compose interface and all seven migrations remain intact. Python now has API (default) and worker targets with distinct healthchecks, SIGTERM defaults and a shared non-root, root-owned-source runtime. Web uses standalone output and removes unused bundled npm/Yarn/corepack runtime trees. Base/uv images are digest-pinned; root application dependency locks are unchanged. Poppler/Tesseract English remain available. Build context excludes secrets, runtime/build caches, credentials, Git and local evidence. APT repositories remain time-dependent; retain tested image digests rather than claiming bit-identical rebuilds.

`compose.release.yml` is a standalone, separate private project with independent named volumes, an internal backend network, loopback-only web port, no infrastructure/admin/API published ports, resource/PID limits, read-only application filesystems, restricted capabilities, init/restart policies and 90-second worker termination. Migrations are an explicit maintenance-profile one-shot, without seed/downgrade. API/worker preflight verifies identity mode, PostgreSQL/RabbitMQ requirements and exact schema before startup. Production identity is still unsupported and rejected; only explicit private local-mode rehearsals run. No separate dispatcher is introduced: the existing supervised recovery bootstep is retained.

PR/main/manual/reusable CI provisions fresh hosted-runner services and synthetic data. It pulls the reviewed PostgreSQL/RabbitMQ digests from the release file without changing development configuration, then reuses the established bootstrap/check/reliability/browser commands. It includes schemas/clients/fixtures, offline evaluations, migration/restore verification, Linux OCR, real service failures and Docker builds. No cloud credentials or live Gemini calls are part of ordinary CI. SHA-pinned current stable official actions were resolved and their expected inputs verified against official source metadata: checkout 7.0.1, setup-node/setup-python 7.1.0, upload-artifact 7.0.2, buildx 4.4.1 and login 4.6.0. Checkouts do not persist credentials. Permissions, concurrency and artifact paths are restricted.

Manual-tag GHCR publishing is prepared for three first-party images with SHA/version tags, OCI source/revision/version labels, registry digest reporting and no `latest` tag. It requires explicit repository opt-in, protected review, verified remote/commit/token/unused tags and passing tests/image vulnerability gate. Only that job has package write permission; Actions read permission is used to inspect environment protection. No publication, remote configuration, public deployment or billing change occurred.
